4. Scripts SQL

Le cours liste Encadreur parmi les classes, mais le script de l'annexe C ne crée pas sa table. Pour que EF-04 (affecter un encadreur) soit réalisable, on ajoute la table encadreur et une clé étrangère nullable encadreur_id dans demande_stage.

Fichier 001_schema.sql (dossier TP3/) :

CREATE TABLE etudiant (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(60) NOT NULL,
  prenom VARCHAR(60) NOT NULL,
  email VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE entreprise (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(80) NOT NULL,
  ville VARCHAR(60)
);

CREATE TABLE encadreur (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(60) NOT NULL,
  prenom VARCHAR(60) NOT NULL,
  email VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE demande_stage (
  id INT PRIMARY KEY AUTO_INCREMENT,
  etudiant_id INT NOT NULL,
  entreprise_id INT NOT NULL,
  encadreur_id INT NULL,                       -- 0..1 encadreur (EF-04)
  statut VARCHAR(10) NOT NULL DEFAULT 'BROUILLON',
  motif_refus VARCHAR(255) NULL,
  FOREIGN KEY (etudiant_id) REFERENCES etudiant(id),
  FOREIGN KEY (entreprise_id) REFERENCES entreprise(id),
  FOREIGN KEY (encadreur_id) REFERENCES encadreur(id)
);

CREATE TABLE soutenance (
  id INT PRIMARY KEY AUTO_INCREMENT,
  demande_id INT NOT NULL UNIQUE,              -- UNIQUE = 0..1 soutenance par demande
  date_heure DATETIME NOT NULL,
  salle VARCHAR(20),
  FOREIGN KEY (demande_id) REFERENCES demande_stage(id)
);
  • encadreur_id est nullable : c'est la multiplicité 0..1 côté encadreur.
  • demande_id NOT NULL UNIQUE dans soutenance traduit « 0..1 soutenance par demande » : la base refuse un doublon même si le code applicatif oublie de le vérifier.

5. Vérification par COUNT(*)

Fichier 003_verification.sql :

SELECT 'etudiant' AS t, COUNT(*) AS n FROM etudiant
UNION ALL SELECT 'entreprise',    COUNT(*) FROM entreprise
UNION ALL SELECT 'encadreur',     COUNT(*) FROM encadreur
UNION ALL SELECT 'demande_stage', COUNT(*) FROM demande_stage
UNION ALL SELECT 'soutenance',    COUNT(*) FROM soutenance;
