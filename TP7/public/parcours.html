Parcours responsable — 3 écrans

  1. Connexion
  2. Liste des demandes à traiter
  3. Décision : soumettre / valider / refuser
Écrans, actions et appels API
ÉcranAction utilisateurAppel / résultat
1. connexion.htmlSaisir les identifiants responsablePOST /api/connexion → redirection vers responsable.html
2. responsable.html (liste)Arrivée, clic sur « Rafraîchir » ou actualisation automatiqueGET /api/demandes → tableau reçu de la base
3. responsable.html (décision)Choisir un statut, saisir un motif si refus, enregistrerPATCH /api/demandes/{id}/statut → 200, puis relecture immédiate de la liste

La transition suit l'ordre métier : BROUILLON → SOUMISE → VALIDEE. Un refus sans motif renvoie 400 et le message s'affiche sous le champ prévu à cet effet.

Choix d'interface

  • Une seule page par rôle, avec des sections correspondant aux écrans du parcours : moins d'allers-retours, mais des sections clairement titrées.
  • Un bouton « Rafraîchir » explicite, complété par une actualisation automatique : les données affichées reviennent toujours de la base.
  • Aucun lien direct vers les routes API : tout passe par fetch dans public/js/api.js.
