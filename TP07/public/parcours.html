Deux parcours, une interface unifiée

La connexion se fait depuis la page d'accueil. Ensuite, un seul espace (app.html) s'adapte au rôle connecté : tableau de bord, demandes, soutenances, historique et profil. Les anciennes pages connexion.html, etudiant.html et responsable.html sont conservées mais redirigent vers cette interface commune.

Parcours étudiant

Connexion → dépôt → soumission → suivi
Étape dans l'interfaceAction utilisateurAppel API / résultat
1. ConnexionCompte de démonstration ou inscriptionPOST /api/connexion ou /api/inscription → ouverture de app.html
2. Tableau de bordLecture des compteurs et des cartesGET /api/demandes/mes, /api/soutenances
3. Nouvelle demandeChoisir une entreprise dans la modalePOST /api/demandes → 201, statut BROUILLON
4. SoumettreBouton « Soumettre » sur sa propre cartePATCH /api/demandes/{id}/statut → SOUMISE
5. Détail / HistoriqueOuvrir les modales dédiéesGET /api/demandes/{id}/historique (jeton CSRF + droit sur la demande)

Toutes les valeurs affichées passent par textContent : un motif contenant <script>alert(1)</script> s'affiche comme du texte, sans créer de balise ni exécuter de code (voir preuves/test_balises.txt).

Parcours responsable

Connexion → décision → soutenance → journal
Étape dans l'interfaceAction utilisateurAppel API / résultat
1. ConnexionCompte responsable depuis l'accueilPOST /api/connexion → rôle responsable
2. Toutes les demandesRecherche, filtres, bouton « Actualiser »GET /api/demandes → tableau complet avec noms et entreprises
3. Décision« Valider » ou « Refuser » (motif obligatoire)PATCH /api/demandes/{id}/statut → 200, relecture immédiate
4. SoutenanceProgrammer une date et une sallePATCH /api/demandes/{id}/soutenance → agenda mis à jour
5. HistoriqueOuvrir le journal d'une demandeGET /api/demandes/{id}/historique → auteurs et horodatages

La transition suit l'ordre métier : BROUILLON → SOUMISE → VALIDEE. Un refus sans motif renvoie 400 ; le message s'affiche dans une notification lisible, sans page blanche.

Choix d'interface

  • Une coque commune et des vues clairement titrées, au lieu d'une page séparée par rôle : moins d'allers-retours, un rendu homogène.
  • Un bouton « Actualiser » explicite, complété par une relecture automatique toutes les 15 s lorsqu'aucune modale n'est ouverte et qu'aucun champ n'a le focus.
  • Aucun lien direct vers les routes API : tout passe par fetch dans assets/js/api.js (session, CSRF, erreurs 400/401/500).
